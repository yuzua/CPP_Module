# CPP Module 01 — 何を学ぶモジュールか

42 Common Core の **CPP Module 01** は、Module 00 で触れた **クラス** を前提に、**オブジェクトがどこに置かれ、どう寿命を持ち、どう指されるか** を学ぶモジュールである。

C++ らしい表現（`new` / `delete`、参照、ファイル I/O と文字列操作）を、小さなプログラムに分けて段階的に身につける。課題 PDF の手順書ではなく、**モジュール全体の地図**として読む。

各演習の実装メモ・深掘りは `ex00/README.md` 〜 `ex02/README.md`、ex03 は `ex03/README.md`（モジュール横断の整理を含む）、ex04 は `ex04/architecture.md` など、ex05 は `ex05/architecture.md` を参照。

## 1. Module 01 の位置づけ

| 観点 | Module 00 | Module 01 |
|------|-----------|-----------|
| 中心テーマ | クラスの作り方、メンバー、入出力の基本 | **メモリ**（スタック / ヒープ）と **指し方**（ポインタ / 参照） |
| 典型パターン | `.hpp` / `.cpp` 分割、コンストラクタ、const | `new` / `delete`、参照メンバー、ファイルと文字列 |
| ゴール | 「クラスとして設計して動かす」 | 「寿命と別名を理解し、設計でポインタと参照を選べる」 |

Module 01 全体のテーマは **メモリとその指し方**。同じオブジェクトを、スタック上・ヒープ上・ポインタ経由・参照経由で見る練習が、ex00 から ex03 まで一本の線でつながっている。ex04 は **クラスを使わないユーティリティ**としてファイル I/O と文字列処理、ex05 は再び **クラス** で **メンバ関数ポインタ** による呼び分けを扱う。

## 3. 演習ごとに学べること

| 演習 | 課題名（subject） | ざっくり作るもの | 主に学べる内容 |
|------|-------------------|------------------|----------------|
| **ex00** | BraiiiiiiinnnzzzZ | `Zombie` クラスと、ヒープ / スタックに1体ずつ作る工場関数 | **スタック vs ヒープ**、オブジェクトの**寿命**、**コンストラクタ / デストラクタ**のタイミング、`new` / `delete`、ポインタ `->`、`.hpp` / `.cpp` と**宣言・定義・リンク**、引数の `const std::string&`、`const` メンバー関数 |
| **ex01** | Moar brainz! | `new[]` で N 体のゾンビを**1回の確保**で作る `zombieHorde` | **`new[]` / `delete[]`**（`new` / `delete` との対応）、**配列がデフォルトコンストラクタを要求する理由**、setter や代入で名前を入れる設計、配列ポインタと `horde[i]`、メモリリークの防止 |
| **ex02** | HI THIS IS BRAIN | `main.cpp` のみ（クラスなし） | **ポインタ**（アドレスを保持する変数）と**参照**（既存オブジェクトの別名）、`&` / `*`、アドレス出力と値出力が3通りで一致すること、ポインタ変数自身のアドレス `&stringPTR` との違い |
| **ex03** | Unnecessary violence | `Weapon`、`HumanA`（武器を**参照**で保持）、`HumanB`（武器を**ポインタ**で保持） | **参照メンバー**（初期化必須・NULL 不可）と**ポインタメンバー**（未武装 = `NULL`）の**設計判断**、`const` 参照の getter、複合文 `{}` によるスコープと破棄順、他オブジェクトへの参照の寿命 |
| **ex04** | Sed is for losers | `./replace file s1 s2` — ファイルを読み、`s1` を `s2` に置換して `file.replace` に書く | **`std::ifstream` / `std::ofstream`**、**`argc` / `argv`**、文字列の **`find` / `append` / `substr`** による置換（`std::string::replace` は禁止）、読み取り失敗・引数不足への対応、**関心の分離**（CLI / 純粋置換関数 / I/O） |
| **ex05** | Harl 2.0 | `Harl` クラス — `complain("DEBUG")` 等でレベルに応じたメッセージを出力 | **private** の `debug` / `info` / `warning` / `error`、**public** の `complain`、`void (Harl::*)()` **メンバ関数ポインタ**と `(this->*ptr)()`、レベル文字列とポインタ配列の対応、**if/else if/else の森による dispatch は禁止**（評価） |

ex02 は **必須**、ex03・ex04 はカリキュラム上 **任意**（提出ポリシーは campus の subject に従う）だが、Module 02 以降の理解には ex03 が特に効く。ex05 は **任意**（ex06 Harl filter とセットで switch 演習に続く）。

## 4. ex00 → ex05 の流れ

```text
ex00  どこにオブジェクトを作るか（スタック / ヒープ）
  ↓
ex01  ヒープ上で N 個をまとめて確保（配列）
  ↓
ex02  1つのオブジェクトをポインタと参照で「同じ実体」として見る
  ↓
ex03  クラスのメンバーとして参照 vs ポインタを選ぶ（常に武装 vs 武器なしあり）
  ↓
ex04  クラス外の関数 + ファイル I/O + 文字列（Module 00 の argv の延長）
  ↓
ex05  クラスに戻る — メンバ関数ポインタで complain → debug/info/warning/error
```

**ex00〜ex03** … Zombie / Weapon の小さな世界で、C++ のメモリモデルと別名のルールを体で覚える。

**ex04** … sed 相当の置換を C++ だけで書き、標準ライブラリの文字列とストリームに慣れる。クラスが必須ではないが、**関数の分割**と**エラー処理**の練習になる。

**ex05** … 出力用の private メソッドを **public の `complain` 1本** から呼び分ける。**データメンバのポインタ（ex02〜03）** とは別に、**関数のアドレス** を表す **ポインタ to メンバ関数** を学ぶ。ex06 では同じ `Harl` を **`switch` + fall-through** でフィルタする（任意演習）。

## 5. 共通ルール・制約

- コンパイル: **C++98**（`-std=c++98`）。C++11 以降の機能は subject 上使えない。
- 禁止例: `using namespace std;`、C の `printf` 系、多くの演習では **`malloc` / `free`**、Module 01 では **`std::vector` 等の STL コンテナ**（ex04 の文字列 `std::string` と iostream は許可）。
- ヒープを使う ex00 / ex01 は **valgrind** でリークがないことを確認する習慣をつける。

## 6. Module 02 に向けて

Module 01 で固めた内容は、Module 02 で次のように発展する。

| Module 01 で触れたこと | Module 02 での続き |
|------------------------|-------------------|
| デストラクタ、`delete` | **Orthodox Canonical Form**（コピーコンストラクタ、コピー代入、Rule of Three） |
| 参照（ex02, ex03） | **演算子オーバーロード**（参照が導入された本来の用途） |
| ポインタメンバー | **浅いコピー / 深いコピー** |
| メンバ関数ポインタ（ex05） | コールバック風 dispatch の土台（高度な設計では `std::function` 等へ） |
| `const` メンバー関数・`const&` | 固定小数点数クラスなどでの読み取り専用 API |
