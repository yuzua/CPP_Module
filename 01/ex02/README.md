## 1. 課題の目的

ex02 の核心は **「参照は別物ではなく、同じメモリへの別名である」** ことを確認すること。

| 学ぶこと | 内容 |
|----------|------|
| ポインタ | アドレスを保持する変数。`*` で中身にアクセス |
| 参照 | 既存オブジェクトの別名。構文は変数と同じ |
| アドレスと値 | 同じオブジェクトを3通りで見ると、全部同じ結果になる |

> 参照は完全に新しい概念というより、**アドレス操作のための別構文**。

## 3. 実装の要点

```cpp
#include <iostream>
#include <string>

int main(void) {
    std::string const str = "HI THIS IS BRAIN";
    std::string* stringPTR = &str;
    std::string& stringREF = str;

    // アドレス
    std::cout << &str << std::endl;
    std::cout << stringPTR << std::endl;
    std::cout << &stringREF << std::endl;

    // 値
    std::cout << str << std::endl;
    std::cout << *stringPTR << std::endl;
    std::cout << stringREF << std::endl;

    return 0;
}
```

課題では変数名 `stringPTR` / `stringREF`、文字列 `"HI THIS IS BRAIN"` が指定されている。

---

## 4. 3つの見方：変数・ポインタ・参照

```
メモリ上に str という箱が1つ

str         … 本体（中身: "HI THIS IS BRAIN"）
stringPTR   … str の場所を書いたメモ帳（アドレスを保存）
stringREF   … str の別名（同じ箱を指す）
```

| 行 | コード | 意味 |
|----|--------|------|
| 本体 | `std::string const str = "HI THIS IS BRAIN";` | スタック上に文字列オブジェクト |
| ポインタ | `std::string* stringPTR = &str;` | `str` のアドレスを保持 |
| 参照 | `std::string& stringREF = str;` | `str` の別名 |

---

## 5. アドレス出力の読み方

| 式 | 出力するもの |
|----|-------------|
| `&str` | `str` 本体のアドレス |
| `stringPTR` | ポインタが **指している先** のアドレス |
| `&stringREF` | 参照の **実体**（= `str`）のアドレス |

**3つとも同じアドレスになる。**

### 混同しやすい点

```cpp
stringPTR     // str のアドレス（指している先）
&stringPTR    // ポインタ変数自身のアドレス（別の番地）
```

ex02 が求めるのは **str のアドレス** なので、`stringPTR`（`&` なし）が正しい。

---

## 6. 値出力の読み方

| 式 | 意味 |
|----|------|
| `str` | 変数として中身を読む |
| `*stringPTR` | ポインタが指す先の中身（**間接参照**） |
| `stringREF` | 別名として中身を読む |

**3つとも `"HI THIS IS BRAIN"` になる。**

```cpp
stringPTR   →  0x7ffe0010（番地）
*stringPTR   →  その番地の中身
stringREF   →  同じ中身（別名）
```

## 7. 低レイヤー：メモリ上で何が起きているか

### スタック上の配置

```
高アドレス
┌────────────────────────────────────────────┐
│  main のスタック                            │
│                                            │
│  0x7ffe0008  ┌──────────────┐              │
│              │ stringPTR    │              │
│              │ 0x7ffe0010   │──┐           │
│              └──────────────┘  │           │
│                                │           │
│  0x7ffe0010  ┌──────────────┐  │           │
│              │ str          │←─┘           │
│              │ stringREF    │  （別名）     │
│              │ "HI THIS..." │              │
│              └──────────────┘              │
└────────────────────────────────────────────┘
低アドレス
```

### ポインタ：独立したストレージがある

```cpp
std::string* stringPTR = &str;
```

- `stringPTR` 自体もスタック上の変数（例: 8バイト）
- 中身は **アドレス値**（番地）
- 「番地を書いたメモ帳」

### 参照：別名（新しい実体は作らない）

```cpp
std::string& stringREF = str;
```

- **新しい `std::string` オブジェクトは作らない**
- 言語上、`stringREF` は `str` の **別名**
- コンパイラは内部で「`stringREF` → `str` のアドレスを使え」と解釈することが多い

### storage と object（ex01 からの接続）

| 概念 | ex02 での例 |
|------|------------|
| storage | スタック上の `str` が占めるバイト列 |
| object | その上に構築された `std::string` |
| ポインタ | object への **アドレス値** を保持する別変数 |
| 参照 | object への **別名** |

## 8. ポインタ vs 参照

### 比較表

| | ポインタ `T*` | 参照 `T&` |
|---|--------------|----------|
| 新しいストレージ | **ある**（アドレスを保存） | **ない**（別名） |
| 宣言 | `T* p = &obj;` | `T& r = obj;`（**初期化必須**） |
| アクセス | `*p` | `r`（そのまま） |
| 再代入 | 別オブジェクトを指せる | **不可** |
| null | あり得る | **なし** |
| sizeof | ポインタサイズ（8バイト等） | 実体のサイズ |
| 低レイヤー | アドレス値を保持する変数 | コンパイラがアドレスを直接使うことが多い |

### たとえ

| | イメージ |
|---|---------|
| ポインタ | **住所メモ**。手帳は独立。後から別の住所に書き換え可能 |
| 参照 | **ニックネーム**。同じ人の別の呼び方。付け替え不可 |

### 似ている点と違う点

**似ている:** どちらも `str` 以外の経路で同じオブジェクトにアクセスできる。

**違う:**

```
ポインタ = アドレスを持つ独立した変数
参照     = 再代入不可の別名
```

### 具体例

```cpp
// ポインタ：指し先を変更できる
stringPTR = &otherStr;  // OK

// 参照：指し替え不可
// std::string& r;       // NG：初期化必須
// stringREF = otherStr; // これは指し替えではなく値の代入
```

## 9. 演算子の整理

| 記号 | 文脈 | 意味 | 例 |
|------|------|------|-----|
| `&` | 単項演算子 | アドレスを取る | `&str` |
| `&` | 型 | 参照型 | `std::string&` |
| `&` | 関数引数 | 参照で受け取る | `void f(std::string& s)` |
| `*` | 単項演算子 | デリファレンス | `*stringPTR` |
| `*` | 型 | ポインタ型 | `std::string*` |

### 読み方の練習

```cpp
std::string* stringPTR = &str;
//           ^ ポインタ型    ^ str のアドレス

*stringPTR
// ポインタが指す中身

std::string& stringREF = str;
//           ^ 参照型      ^ 初期化必須
```

## 10. const との関係

```cpp
std::string const str = "HI THIS IS BRAIN";
// または
const std::string str = "HI THIS IS BRAIN";
```

- `str` の中身は書き換え不可
- ポインタ・参照経由でも const オブジェクトの変更は不可

```cpp
*stringPTR = "OTHER";   // NG
stringREF = "OTHER";    // NG
```

より厳密に書くなら:

```cpp
const std::string* ptr = &str;   // const へのポインタ
const std::string& ref = str;    // const 参照
```

ex02 では `const str` だけでも要件は満たせる。

## 13. 追加で理解しておくこと

### 関数引数での参照（次のステップ）

Module 00 以降よく使うパターン:

```cpp
void setName(const std::string& name);  // コピーを避ける
```

- 値渡し: コピーが発生
- 参照渡し: 別名として渡す（コピーなし）
- `const&`: 読むだけ（変更不可）

ex02 で「参照 = 別名」を理解すると、コンストラクタの `const std::string& name` の意味もつながる。

### ポインタ演算（ex01 から）

```cpp
horde + i   // i 体先のアドレス
horde[i]    // 同上
```

ポインタは **アドレス値** なので、算術演算ができる（参照は不可）。

### 参照が使われる理由（現場）

| 用途 | 理由 |
|------|------|
| 関数引数 | コピー回避 + null にならない |
| 演算子オーバーロード | 自然な構文 |
| 範囲 for（C++11〜） | 内部で参照を使う |

### コンパイラの実装（知識として）

多くのコンパイラは参照を **内部的にポインタと同様** に実装する。  
ただし言語上のルール（再代入不可、null 不可等）は異なる。

## 14. よくある間違い

| 問題 | 原因 |
|------|------|
| `&stringPTR` を出力 | ポインタ自身のアドレスになる（str とは異なる） |
| `stringPTR` で値を出力 | アドレスが出力される（`*` が必要） |
| 参照の未初期化 | `std::string& r;` はコンパイルエラー |
| `#include` 忘れ | `<iostream>`, `<string>` が必要 |
| 参照を「新しい変数」と思う | 別名。新しいオブジェクトではない |
| ポインタと参照を完全同一視 | 似ているが、ルールが異なる |

## 16. ex03 に向けて

ex03「Unnecessary violence」では **Weapon クラス** と **HumanA / HumanB** が登場。

| クラス | 武器の持ち方 |
|--------|-------------|
| `HumanA` | コンストラクタで `Weapon&`（参照）を受け取る。常に武装 |
| `HumanB` | 最初は武器なし。`setWeapon(Weapon*)` でポインタ |

課題の問い:

> Weapon への **ポインter** を使うのが適しているのはどんな場合か？  
> **参照** を使う場合は？

ex02 の理解:

- **参照** = 常に存在するものへの別名（null 不可）
- **ポインタ** = 存在しない可能性があるもの（null 可）

が ex03 の設計判断に直結する。
