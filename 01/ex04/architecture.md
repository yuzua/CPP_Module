# ex04 Architecture — Sed is for losers

CPP Module 01 ex04 の設計メモ。課題を「何を作るか」「なぜこの形にするか」から整理する。

実装の参照用に、**既存の `main.cpp` 等は触らず**、同じ設計を反映した **`_*` 付きファイル**（`main_.cpp`, `replace_.hpp`, …）を置いている。提出・評価用に公式名へ揃えるときは、内容をコピーしてリネームすればよい。

---

## このプログラムは何をするか

コマンドラインから **3 つの引数** を受け取る。

```text
./replace <filename> <s1> <s2>
```

| 引数 | 意味 |
|------|------|
| `filename` | 読み込むファイル |
| `s1` | 探す文字列（置換の元） |
| `s2` | 置き換え後の文字列 |

やることは次の 2 步だけに見える。

1. `filename` の中身をすべて読む  
2. 文中の **s1 をすべて s2 に変えた結果** を、**`filename.replace`** という新しいファイルに書く  

例: `notes.txt` に `hello world` があり、`s1=world`, `s2=42` なら → `notes.txt.replace` に `hello 42` が入る。

---

## 課題のルール（守ること・禁止）

| 項目 | 内容 |
|------|------|
| 禁止 | `std::string` の **`replace` メンバ関数** |
| 禁止 | C 言語のファイル関数（`fopen`, `fread`, `fwrite` など） |
| 許可 | それ以外の `std::string` の機能（`find`, `append`, `substr` など） |
| 許可 | C++ のファイルストリーム（`std::ifstream`, `std::ofstream`） |
| 必須 | 変な入力やエラーに耐えること |
| 必須 | **自分でテスト** を用意すること |

※ 自作の関数を `replace` や `replaceAll` と名付けるのは **OK**。禁止されているのは **`some_string.replace(...)` というメンバ呼び出し** だけ。

---

## 置換のルール（仕様の細かい部分）

設計で次のように決めている。

| ルール | 説明 | 例 |
|--------|------|-----|
| **左から順** | 文字列の先頭に近い一致から処理する | — |
| **重ならない** | 1 回置換した直後から、もう一度 s1 を探す | `"aaaa"` で `s1="aa"`, `s2="b"` → `"ba"`（先頭 2 文字だけ `"b"` になり、残り `"aa"` はもう一度先頭から） |
| **s1 は空にしない** | 空だと「どこでも一致」になり得て危険なので、プログラム開始時に **エラー** とする | `s1=""` → 終了コード 1 |
| **s1 が無い** | 内容は **元ファイルと同じ** | `"abc"` で `s1="x"` → 出力も `"abc"` |
| **出力ファイル名** | 必ず `<filename>.replace` | `a/b.txt` なら `a/b.txt.replace`（単純に末尾に `.replace` を付ける） |

## 全体の流れ（誰が何を担当するか）

```text
  ユーザー
     │
     ▼
  main_.cpp  … 引数チェック、ファイルを開く／閉じる、エラー表示
     │
     │  全文を std::string に読む
     │
     ▼
  replaceAll()  … 文字列の中だけ s1 → s2（replace_.hpp / replace_.cpp）
     │
     │  置換後の文字列
     │
     ▼
  main_.cpp  … filename.replace に書き込む
```

**ポイント**: 「ファイル」と「置換ロジック」は **別の場所** に分ける。置換の中身を直しても、引数の数え方やファイル名の付け方は `main` 側だけ触ればよい。

## 各ファイルの役割

### `replace_.hpp` — 「置換」の約束だけ書く

- 中身: `replaceAll` という関数の **宣言** だけ  
- **ファイルの読み書きは書かない**  
- 他の `.cpp` から `#include "replace_.hpp"` して使う  

```cpp
std::string replaceAll(const std::string& content,
                       const std::string& s1,
                       const std::string& s2);
```

**意味**: 「この 3 つを渡したら、置換後の新しい文字列を返す」という **契約（約束）**。

---

### `replace_.cpp` — 置換のやり方（アルゴリズム）

- **状態を覚えない**（メンバ変数なしの **自由関数**）  
- `std::string::replace` は使わない  
- 典型パターン:
  1. 今どこまで読んだか `pos` を覚える  
  2. `content.find(s1, pos)` で次の s1 を探す  
  3. 見つかったら、それより前を結果に足し、s2 を足し、`pos` を **一致の直後** に進める  
  4. 見つからなくなったら、残りを足して return  

同じ入力なら常に同じ出力 → **テストしやすい**。

---

### `main_.cpp` — プログラムの入口（CLI）

担当すること:

| 処理 | 失敗したら |
|------|------------|
| 引数が 3 つ（+ プログラム名で計 4 個）か | Usage を stderr、終了 1 |
| s1 が空でないか | メッセージ、終了 1 |
| 入力ファイルを開けるか | メッセージ、終了 1（`.replace` は作らない） |
| 出力ファイルに書けるか | メッセージ、終了 1 |

ファイルは **C++ のストリーム** で開く。スコープを抜けると自動で閉じる（**RAII**）。Module 02 以降で「自分で RAII クラスを書く」練習の土台になる。

---

### `Makefile_`

- コンパイル: `-Wall -Wextra -Werror -std=c++98`（Module 01 の慣習）  
- リンク: `main_.cpp` + `replace_.cpp` → 実行ファイル **`replace_`**  
- `make -f Makefile_ test` で `tests_/run_tests_.sh` を実行（任意）

## なぜ「置換用クラス」を作らないのか

クラスが特に効くのは次のようなときだ。

- **インスタンス変数** があり、それらの間に「常に守るルール」（不変条件）がある  
  - 例: `PhoneBook` の「件数」と「配列の有効範囲」  
- **開いたリソース** をオブジェクトの寿命に結びつけたい（RAII）  
  - 例: 自分で書くファイルハンドルクラス（Module 02 以降）

今回の置換は:

- 入力 3 つ → 出力 1 つ、**覚える状態がない**  
- ファイルの開閉は **`main` + 標準ストリーム** で足りる  

だから **関数 1 本 + ファイル分割** で十分。  
「処理をまとめる」だけなら **名前空間や別 `.cpp` ファイル** でもでき、**空っぽに近いクラス** を作る必要はない（`class.md` も同じ結論）。

## エラー処理の方針

| 状況 | 振る舞い |
|------|----------|
| 引数不足・過多 | stderr に Usage、終了コード **1** |
| s1 が空 | stderr に理由、終了 **1** |
| 入力が開けない | stderr、終了 **1**、出力ファイルは作らない |
| 出力が書けない | stderr、終了 **1** |
| 成功 | 終了 **0**、`filename.replace` ができる |

メッセージの文言は課題で固定されていない。どのエラーでも **終了コードを揃える** ことがテストしやすい。

## テスト（tests_/）

課題は「自分でテストを作る」ことを要求する。設計上は次をカバーする。

| ID | 内容 |
|----|------|
| T-REP-01 | 通常置換（`l` → `L`） |
| T-REP-02 | 重なり（`aaaa` / `aa` / `b` → `ba`） |
| T-REP-03 | s1 が無い → 内容不变 |
| T-CLI-01 | 引数が足りない → 終了 ≠ 0 |
| T-CLI-02 | s1 空 → 終了 ≠ 0 |
| T-CLI-03 | 存在しないファイル → 終了 ≠ 0 |
| T-CLI-04 |  fixture ファイルで `.replace` が期待と一致 |

シェルスクリプトで **終了コード** と **ファイル内容の diff** を oracle にする。
